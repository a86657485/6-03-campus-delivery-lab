# 校园配送实验室实施与验收

用户已确认：六年级第3课，40分钟，一人一机，前置理解一般，无实物，定制二维写实仿真实验。完整应用包含六年级身份选择、逐关积分、教师班级大屏。独立目录实现，不修改旧课。

## 结构
- rules.js：共享纯规则，手动行驶重演、配送方案判定、障碍策略和独立评价。
- server.cjs：复用现有 Node SQLite 课堂服务，六年级名单、独立 cookie、权限、进度版本、服务端验证与去重积分。
- index.html / app.js / style.css / scene.js：学生登录、演示、三个实验、解释、迁移评价、选做参数实验、导出。
- teacher.html / teacher.js：教师认证、班级统计、关卡进度、首答/最近表现、个人详情。
- assets：生成校园背景；运动对象、碰撞、路径和中文为确定性页面绘制。
- runtime：私有数据库及教师密码；不向网页开放。

## 实施顺序与验证
- [x] 先定义和测试模型：碰撞停止、目标停止、动作重演、遗漏停止/提醒、两种障碍规则、参数控制变量、评价答案。
- [x] 实现独立课堂服务：导入601—606名单；验证越权拒绝、跨身份隔离、重复积分、重启保存和并发冲突。
- [x] 实现二维场景与三个递进实验：真实状态驱动、暂停/重试、三级提示、方案变化需重测、首答与修改证据。
- [x] 实现同步与大屏：本机待同步、身份核对、冲突提示与导出、演示不写真实数据。
- [x] 浏览器走通错误—按卡点提示—修订—成功—迁移；检查名单搜索、教师认证、大屏和导出。实际浏览器视口为1280×720时无横向溢出；当前浏览器工具的最小内容宽度仍为1280，1024×768需在校内学生机实测。
- [x] 独立审查并修复问题，交付一键启动、40分钟教学说明和实际验收记录。

## 课堂主线
0—4登录导入；4—14手动控制与关键片段回看；14—25自动配送设计；25—32障碍规则验证；32—37独立评价；37—40保存与交流。全部时间为设计预估。

## 优化记录
- 手动控制证据由笼统理由改为真实操作片段的“观察—决定—结果”。
- 自动配送增加到站提醒方式及使用情境理由；任务顺序的画面与反馈使用同一执行状态。
- 障碍试验在机器人真正到达后才算完成，并提供两种规则的选做比较。
- 独立评价改为判断、修复和解释；未提交不计完成。
- 教师大屏增加三类班级问题汇总，区分历史积分与当前版本。
- 学生端保存增加普通局域网 HTTP 环境的事件编号兼容方案。

## 数据接口约定
GET /api/classes -> {classes}; GET /api/roster?class=601 -> [{id,name,manual}]
POST /api/login {classId,id} 或 {classId,name}; GET /api/me -> {student,version,payload,awards,points,updated}
POST /api/progress {sid,eventId,version,payload}; POST /api/logout {role}
POST /api/teacher/login {password}; GET /api/teacher/class?class=601
payload={stage:'intro',records:{},completions:{},archives:[]}; rules.stages=[{id, title, points}], rules.validPayload(payload), rules.completed(stage,record)
关卡 intro/manual/design/obstacle/assessment，均为必做；参数实验独立选做。完成证明由共享规则重算，存入 completions 保留历史通关，最新实验表现另外显示。

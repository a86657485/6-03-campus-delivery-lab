# 校园配送实验室

六年级信息科技《第3课 我是小小控制员》课堂应用。面向40分钟、一人一机的机房课，通过校园图书配送情境完成“亲自控制—安排自动任务—应对新情况—编写指令—20题考核—设计送书机器人”。

学生以“校园小小控制员”的第一人称身份，完成沉浸式剧情《阅读节前的最后一箱书》。岚老师和配送机器人小达在七个环节中提出需求和运行反馈。剧情可跳过、回看，不代替关卡学习证据。

四项动手实验依次是手动控制、安排配送任务、遇障碍规则和逐条编程。程序要先预测、执行、定位出错指令，再修订并重测，保留前后运行记录。考核每次20题，分四组显示，首次与最近成绩分开保存；答完后进入教材第21页的送书机器人设计表。选择三项功能时，每项都会触发一次组装升级；自定义功能作为作品保存，未仿真验证的创意会标明。

## 启动

1. 双击 [启动课堂.command](启动课堂.command)。
2. 教师电脑会打开教师大屏和密码文件。
3. 让学生访问启动窗口中显示的“学生访问”地址。教师电脑本机可使用 `http://localhost:8784`。
4. 首次启动如果 macOS 询问是否允许本地网络连接，请允许。学生电脑需与教师电脑在同一校园网络。

应用会自动使用已导入的601—606班名单。名单中没有的学生可在所选班级手动输入姓名。

## 入口

- 学生端：`http://教师电脑IP:8784/`
- 教师大屏：`http://教师电脑IP:8784/teacher`
- 教师演示：`http://教师电脑IP:8784/demo`（不写入学生积分和进度）

教师大屏密码为 `teacher`。登录教师大屏后，可从页面右上角进入“测试模式”。

## 教师测试模式

测试模式只能在教师登录后进入，不写入学生名单、进度或积分。

- 可以从下拉菜单或顶部导航自由选择七个必做环节。
- 点击“载入标准答案并通过本关”，可检查标准路径、通过页面和累计积分。
- 选做参数实验没有唯一标准答案，可自由调整参数测试。
- 点击“重置测试进度”可回到第一关的空白状态。
- 测试模式默认不强制播放剧情；教师可点击“播放本关剧情”检查任意一幕。

## 数据与备份

- 课堂记录保存在 `runtime/classroom.sqlite`。
- 默认教师密码为 `teacher`，同时保存在 `runtime/teacher-password.txt`。如需临时改用其他密码，可在启动时设置 `TEACHER_PASSWORD`环境变量。
- 学生端“保存实验记录”可导出个人 JSON；教师大屏可导出当前班级记录。
- 课前备份时，退出课堂服务后复制整个 `runtime` 文件夹。

## 40分钟课堂安排

建议导入3分钟；手动控制6分钟、安排自动任务6分钟、遇障碍规则5分钟、编程调试8分钟，这四项动手活动合计约25分钟；20题考核约6分钟、机器人设计约5分钟、保存交流约1分钟。以上是设计预估，不设置强制等待；理解较慢的班级可把考核后的设计作品延伸到下一课时，学习记录仍可保存和恢复。

## 设计边界

- 路线、距离和速度是用于学习的简化仿真，不表示真实机器人的物理性能。
- 自动任务实验提供沿标定路线到达目的地的能力；编程实验则要求学生自己安排前进、转向、停止与提醒的逐条指令。
- 积分表示任务完成，理解程度需结合首答、最近作答、操作记录和修改理由判断。

## 技术检查

在应用目录运行：

```bash
npm test
```

项目无第三方运行依赖，需要 Node.js 22.13 或更高版本。

## 从 GitHub 克隆后启动

仓库不包含真实学生名单、课堂数据库或教师密码。首次启动前，可以先使用虚构名单样例：

```bash
cp roster.example.json roster.json
npm start
```

在真实课堂中，请将 `roster.json` 替换为本校名单生成的本地文件。`roster.json` 和 `runtime/` 已被 `.gitignore` 排除，不会推送到 GitHub。
